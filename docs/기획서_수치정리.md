## 2. 정확도 (개발용 20문항, 3회 반복)

문항은 데이터에서 난수(고정 시드)로 뽑고 정답은 DB를 직접 계산해 만들었습니다(오타 5, 모른다 3 포함). **제가 만든 문항이라 시험용 60문항보다 쉬울 수 있습니다.**

| 지표 | Cloudflare Workers AI (서비스용) | 로컬 gemma4:26b (개발용) |
|---|---|---|
| 자료 선택 정확도 | 95% · 95% · 95% ✅ | 95% · 95% · 95% ✅ |
| 전체 통과 | 19 · 19 · 19 / 20 ✅ | 18 · 18 · 19 / 20 ✅ |
| 숫자·사실 일치 | 93% · 93% · 93% ✅ | 87~93% ✅ |
| "모른다"를 정확히 | 3/3 ✅ | 3/3 ✅ |
| 오타 보정 정답 / 잘못 고친 수 | 5/5 / 0건 ✅ | 5/5 / 0건 ✅ |

- 남은 실패는 두 모델 모두 같은 1문항("가족놀이동삼은 언제 개방해?"): 작은 자료의 장소 이름을 후보 설명에서 못 찾아 거절합니다.
- **시험용 60문항 결과:** ⏳ 시험 후 기입(자료 선택 / 숫자·사실 / 모른다 / 오타 / 평균 시간 / 토큰).
- **알려진 변동:** 같은 질문도 실행마다 결과가 달라질 수 있습니다(프롬프트에 매번 새로 넣는 1회용 난수가 원인, 보안 장치라 유지). 예: "한체산은 언제 설립됐어?"는 시연 점검에서 2회 중 1회 "근거를 찾지 못했어요"로 나왔습니다 ✅. 그래서 정확도는 한 번의 값이 아니라 **3회 반복의 범위**로 보고합니다.

## 4. 안전장치 (심사에서 설명할 근거)

| 장치 | 내용 | 확인 방법 |

| 역할 분리 | 숫자·날짜·판정은 코드, LLM은 해석·선택·설명 ✅ | 설계 |
| 숫자 대조 | 답 속 숫자가 조회 결과에 없으면 숫자를 빼고 표만 보여 줌 ✅ | 테스트(쉼표·소수·전각 숫자 포함) |

| SQL 방어 | LLM이 쓴 SQL을 토큰 분석으로 검사(SELECT만, 허용 표만, 행 수 상한) + DB 읽기 전용 + **실행 시간 2초 제한** ✅ | 무작위 SQL 3만 개를 실제 실행해 우회 없음 확인, 21만 행 자기 조인이 2.00초에 중단 |

| 개인정보 | 질문·답변 원문과 IP 원문을 저장하지 않음, 가명 값은 하루마다 바뀜, 로그 30일 ✅ | 테스트가 로그에 전화번호·IP가 없음을 확인 |

## 7. 한계 (기획서에 솔직하게 적을 것)

1. 개발용 20문항은 자체 제작이라 시험용보다 쉬울 수 있음.
2. 같은 질문의 결과가 실행마다 달라질 수 있음(위 변동).
3. 오픈API 27종은 아직 연결하지 않음(카드만 있음 → "연결 예정"으로 안내하고 개방 수요로 기록).
4. 자료가 2024~2025년 것이 많아 "1년 넘게 갱신 안 됨" 배지로 알려 줌.
5. 같은 2024-07인데 월별 주차 현황(59,808)과 입출차 합(215,528)이 약 3.6배 다름(원인 ❓ 미확인). 섞지 않고 대표 값과 다른 값을 함께 보여 줌.
6. 한글로 쓴 수("삼십 명")는 숫자 대조가 읽지 못해 프롬프트와 별도 검사로 거름.
7. 서비스 배포는 임시 터널로 시연 중이며, 고정 주소(오라클 서버)는 진행 예정.
8. Cloudflare의 데이터 처리는 모델 페이지의 "데이터 비보관" 표기만 확인했고 직접 검증하지 못함.
9. 하루 무료 한도(약 340건)를 넘으면 다음 날까지 AI 답이 멈추고, 화면은 미리 계산한 예시 답으로 안내함.
